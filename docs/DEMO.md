# Демо-сценарий

1. Выполните `Copy-Item .env.example .env`, затем `docker compose up --build -d`. В seed создаются 60 исполнителей, справочники и системные поля.
2. Откройте `http://localhost:5173`, затем нажмите «Создать демо-заявку». Проверьте, что после назначения колонка исполнителя заполнилась.
3. В «Правилах» добавьте тестовый фильтр `executor.vip == true`; запустите «Проверить» и «Dry-run», затем сохраните правило и создайте новую демо-заявку.
4. В «Симуляторе» запустите поток заявок и изменения статусов. Панель обновляется через WebSocket, таблица — также с периодическим запросом.
5. Откройте «Исполнители» и сравните число открытых заявок и дневные лимиты. «Аудит / DLQ» показывает историю назначений и повторную отправку dead outbox записей.
6. Проверьте API АИС на `http://localhost:8001/docs`; для новой заявки используйте поля исходного кейса (`id`, `sum` в webhook-балансиратор; AIS API принимает `amount`, `order_type`, `subject` и т. д.).
7. Нажмите «Экспорт в Excel» и проверьте листы Summary, Executors, Timeline, Fairness и Assignments.

Чтобы попробовать `REASSIGN_ON_DEACTIVATE=true`, задайте флаг в `.env` и пересоздайте Compose-сервисы. Нагрузочные пороги fairness/p95 показывайте только после запуска и заполнения `docs/LOAD_REPORT.md` реальными результатами.
